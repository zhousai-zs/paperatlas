# 检索与上下文设计

## 问题与目标

原实现主要返回约 350 tokens 的检索块，命中页面不代表摘录里有足够的解释。参考文献过滤依赖小节名，遇到图示标题打断、参考文献跨页时会漏掉，实际查询曾将 InstructIR PDF 第 26 页的参考文献作为第二条候选。

此次优化保留离线、只读、无生成模型的边界：改进可检索正文、延长连续证据、减少 Agent 为补上下文而逐页调用的负担。原论文、有效 Markdown 和冻结标注均不修改。

## 参考方案

2026-10-23 查阅的公开一手资料：

- [LangChain ParentDocumentRetriever](https://reference.langchain.com/python/langchain-classic/retrievers/parent_document_retriever/ParentDocumentRetriever)：先检索较小子块，再返回更大的父级文本。借鉴检索粒度与回答上下文分离，不引入框架依赖。
- [PaperQA2 官方仓库](https://github.com/Future-House/paper-qa)：区分检索候选与后续证据处理，控制证据数量和上下文。其模型重排、总结、媒体增强等做法会增加外部模型调用，本次没有引入。

这些是设计参考，不是对这些项目进行过本机性能或准确率比较。

## 当前实现

1. **参考文献按内容对齐。** 将结构化 `ref_text` 对齐到有效 Markdown 的原文范围，忽略排版、空白和重复链接目标，保留原字符偏移。对齐后的参考文献块不参与索引；保守格式识别处理部分缺少对齐的编号条目，小节过滤继续作为补充。正文仍以有效 Markdown 为准，上游修订造成无法对齐时不会按整个页码粗暴删除正文。
2. **保留精细定位。** 最终保留约 350 tokens 的检索块，前缀和特殊 token 仍计入 512 上限。试验过 420 tokens 与句末切分组合：开发集混合 Hit@5 由 80% 升至 85%，但原验收集由 90% 降至 85%，因此未采用。返回上下文独立扩大，不要求嵌入模型压缩整段长解释。未改变嵌入模型、术语表或 RRF 权重。
3. **返回较大连续上下文。** 命中后扩展相邻检索块，范围限制在同页同小节和约 6000 字符内，遇到被排除的文本或标题停止。`excerpt` 与 `source_range` 对应完整返回片段，`match_range` 标记检索定位块，二者都能在原页逐字核对。没有相邻正文时不凑长度；遇到本身超过预算的原始块，保留该块。
4. **按需读取邻页。** `read_page` 可请求前后各两页，主页面完整返回，邻页在共享 24000 字符预算内整页返回。没有返回的邻页列入 `omitted_pages`，避免悄悄截断公式和表格。每页都有独立页码、原页图和证据路径。
5. **以页融合并分散来源。** 混合模式先将同页的两路片段支持合并，避免不同切块 ID 使证据无法形成共识；每页仍保留实际命中块作定位。主题综述或比较可显式设置 diverse=true，每篇最多两页，减少同一篇论文占满候选；具体问题保留默认，单篇深入检索用 doc_id。曾测试默认限制每篇两页，但会压低具体表格/机制问题的证据页覆盖，因此将其作为按任务选择的可选参数。
6. **控制回归。** 保留旧索引备份；冻结 40 条标注不改，先看开发集再运行原验收集；原验收集已用于方案回归选择，最终数字不再视为未见测试。页级命中之外，新增原引句是否直接出现在返回上下文的指标。这仍不等于答案正确率或证据充分性。

## 已知边界

参考文献识别依赖上游结构与文本特征，不能保证所有转换错误都被识别。扩大上下文不能补回未召回的论文，也不能替代 Agent 针对不同子问题分别检索。页级边界仍存在，需要跨页解释时应主动读取邻页。没有加入新的重排模型、向量数据库、自动生成摘要或全篇读取工具；后续应由实际失败案例决定是否需要这些能力。
